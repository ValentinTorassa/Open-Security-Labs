Un servicio falló anoche. Tenés los logs, pero casi todo es ruido: healthchecks, mensajes de debug, logins normales. En el lab de find y grep buscabas una palabra. Ahora necesitás preguntas más finas: **cuántos errores hubo, en qué archivos, qué pasó justo antes de cada uno y a qué usuario le pasó más.**

<Callout type="concepto">
  grep lee línea por línea y se queda con las que coinciden. Con sus opciones
  cambiás qué hace con esas líneas: invertirlas, contarlas, mostrar las de
  alrededor o quedarte solo con el pedazo que coincide.
</Callout>

## Armá los logs de práctica

Todo el lab pasa en `~/lab-grep`, con logs de juguete. En un servidor real serían cientos de líneas; acá son pocas para que puedas comprobar cada salida a ojo.

<TerminalBlock title="vt@labs:~">

```bash
mkdir -p ~/lab-grep/logs
cd ~/lab-grep

cat > logs/app.log << 'EOF'
2026-10-20 03:00:01 INFO  api: servidor iniciado en el puerto 8080
2026-10-20 03:00:05 DEBUG api: healthcheck ok
2026-10-20 03:01:12 INFO  api: login de user_42
2026-10-20 03:01:13 WARN  api: consulta lenta (2300 ms) de user_42
2026-10-20 03:01:14 ERROR api: timeout al conectar con la base, user_42
2026-10-20 03:01:20 DEBUG api: healthcheck ok
2026-10-20 03:02:02 INFO  api: login de user_7
2026-10-20 03:02:03 ERROR api: timeout al conectar con la base, user_7
2026-10-20 03:02:09 INFO  api: reintento exitoso de user_7
2026-10-20 03:03:00 DEBUG api: healthcheck ok
EOF

cat > logs/worker.log << 'EOF'
2026-10-20 03:00:02 INFO  worker: arranca la cola de tareas
2026-10-20 03:01:30 DEBUG worker: sin tareas pendientes
2026-10-20 03:01:45 WARN  worker: la tarea 118 tarda más de lo esperado
2026-10-20 03:01:50 ERROR worker: falló la tarea 118 de user_42
2026-10-20 03:02:30 INFO  worker: reporte de errores enviado
2026-10-20 03:02:40 DEBUG worker: sin tareas pendientes
EOF

echo "ERROR de prueba: no es un log, ignorar" > notas.txt
```

</TerminalBlock>

`cat > archivo << 'EOF'` escribe en el archivo todo lo que pegues hasta la línea `EOF`. Las comillas en `'EOF'` hacen que el shell no toque el texto. Pegá cada bloque completo, desde `cat` hasta `EOF`.

Tu carpeta quedó así:

```text
lab-grep/
├─ logs/
│  ├─ app.log      (10 líneas)
│  └─ worker.log   (6 líneas)
└─ notas.txt       (no es un log, pero dice ERROR)
```

## Sacar el ruido: -v

<TerminalBlock title="vt@labs:~/lab-grep">

```bash
grep -v "DEBUG" logs/app.log
```

</TerminalBlock>

```text
2026-10-20 03:00:01 INFO  api: servidor iniciado en el puerto 8080
2026-10-20 03:01:12 INFO  api: login de user_42
2026-10-20 03:01:13 WARN  api: consulta lenta (2300 ms) de user_42
2026-10-20 03:01:14 ERROR api: timeout al conectar con la base, user_42
2026-10-20 03:02:02 INFO  api: login de user_7
2026-10-20 03:02:03 ERROR api: timeout al conectar con la base, user_7
2026-10-20 03:02:09 INFO  api: reintento exitoso de user_7
```

`-v` invierte la búsqueda: muestra las líneas que **no** coinciden. Las tres líneas de `healthcheck ok` desaparecieron y quedaron 7 de 10.

## Contar y listar: -c y -l

<TerminalBlock title="vt@labs:~/lab-grep">

```bash
grep -c "ERROR" logs/*.log
grep -l "ERROR" logs/*.log notas.txt
```

</TerminalBlock>

```text
logs/app.log:2
logs/worker.log:1
```

```text
logs/app.log
logs/worker.log
notas.txt
```

- `-c` cuenta las líneas que coinciden en cada archivo, sin mostrarlas. Con un solo archivo devuelve solo el número.
- `-l` muestra solo el nombre de los archivos que tienen al menos una coincidencia.

<Callout type="nota">
  `-c` cuenta **líneas**, no apariciones. Si una línea dice `ERROR` dos veces,
  suma 1. Para contar apariciones vas a usar `-o`, más abajo.
</Callout>

## La palabra exacta: -w

<TerminalBlock title="vt@labs:~/lab-grep">

```bash
grep -i "error" logs/worker.log
grep -iw "error" logs/worker.log
```

</TerminalBlock>

```text
2026-10-20 03:01:50 ERROR worker: falló la tarea 118 de user_42
2026-10-20 03:02:30 INFO  worker: reporte de errores enviado
```

```text
2026-10-20 03:01:50 ERROR worker: falló la tarea 118 de user_42
```

Sin `-w`, `error` también coincide adentro de `errores`, y la línea del reporte se cuela como si fuera un error. Con `-w`, grep pide que el patrón sea una palabra entera: que no tenga letras, números ni `_` pegados antes o después.

## Qué pasó antes y después: -B, -A y -C

Encontrar el error es la mitad. La otra mitad es ver qué pasó justo antes.

<TerminalBlock title="vt@labs:~/lab-grep">

```bash
grep -B 1 "ERROR" logs/app.log
```

</TerminalBlock>

```text
2026-10-20 03:01:13 WARN  api: consulta lenta (2300 ms) de user_42
2026-10-20 03:01:14 ERROR api: timeout al conectar con la base, user_42
--
2026-10-20 03:02:02 INFO  api: login de user_7
2026-10-20 03:02:03 ERROR api: timeout al conectar con la base, user_7
```

Antes del primer timeout hubo una consulta lenta: es una pista de que la base ya venía mal. El `--` separa grupos que no están pegados en el archivo.

```text
-B 2    2 líneas antes (Before)
-A 2    2 líneas después (After)
-C 2    2 líneas antes y 2 después (Context)
```

Si sumás `-n`, grep marca con `:` la línea que coincide y con `-` las de contexto:

<TerminalBlock title="vt@labs:~/lab-grep">

```bash
grep -n -C 1 "ERROR" logs/app.log
```

</TerminalBlock>

```text
4-2026-10-20 03:01:13 WARN  api: consulta lenta (2300 ms) de user_42
5:2026-10-20 03:01:14 ERROR api: timeout al conectar con la base, user_42
6-2026-10-20 03:01:20 DEBUG api: healthcheck ok
7-2026-10-20 03:02:02 INFO  api: login de user_7
8:2026-10-20 03:02:03 ERROR api: timeout al conectar con la base, user_7
9-2026-10-20 03:02:09 INFO  api: reintento exitoso de user_7
```

Acá no aparece `--`: con una línea de contexto de cada lado, los dos grupos se tocan (6 y 7 son seguidas) y grep los junta.

## Varios patrones y anclas: -E, ^ y $

<TerminalBlock title="vt@labs:~/lab-grep">

```bash
grep -E "ERROR|WARN" logs/app.log
```

</TerminalBlock>

```text
2026-10-20 03:01:13 WARN  api: consulta lenta (2300 ms) de user_42
2026-10-20 03:01:14 ERROR api: timeout al conectar con la base, user_42
2026-10-20 03:02:03 ERROR api: timeout al conectar con la base, user_7
```

`-E` activa las expresiones regulares extendidas, donde `|` significa "o": líneas con `ERROR` o con `WARN`.

<Callout type="error">
  Sin `-E`, `grep "ERROR|WARN"` busca el texto literal `ERROR|WARN`, que no
  está en ninguna línea: no devuelve nada y no avisa. Si un patrón con `|` no
  encuentra nada, lo primero es revisar que tenga `-E`.
</Callout>

Dos símbolos más para anclar el patrón:

```text
^    principio de la línea
$    final de la línea
```

<TerminalBlock title="vt@labs:~/lab-grep">

```bash
# Lo que pasó en el minuto 03:02
grep "^2026-10-20 03:02" logs/app.log

# Líneas que terminan en user_42
grep "user_42$" logs/*.log
```

</TerminalBlock>

```text
2026-10-20 03:02:02 INFO  api: login de user_7
2026-10-20 03:02:03 ERROR api: timeout al conectar con la base, user_7
2026-10-20 03:02:09 INFO  api: reintento exitoso de user_7
```

```text
logs/app.log:2026-10-20 03:01:12 INFO  api: login de user_42
logs/app.log:2026-10-20 03:01:13 WARN  api: consulta lenta (2300 ms) de user_42
logs/app.log:2026-10-20 03:01:14 ERROR api: timeout al conectar con la base, user_42
logs/worker.log:2026-10-20 03:01:50 ERROR worker: falló la tarea 118 de user_42
```

Con `^`, la fecha y la hora tienen que estar al principio de la línea: así filtrás una ventana de tiempo sin que coincida un número que aparece en el medio del mensaje.

## Extraer y contar: -o con sort y uniq

¿A qué usuario le fallaron más cosas? Hay que quedarse con las líneas `ERROR` y, de cada una, solo con el usuario.

<TerminalBlock title="vt@labs:~/lab-grep">

```bash
grep "ERROR" logs/*.log | grep -o "user_[0-9]*"
```

</TerminalBlock>

```text
user_42
user_7
user_42
```

- El `|` (pipe) le pasa la salida del primer grep al segundo: el segundo ya no lee archivos, lee las líneas `ERROR`.
- `-o` muestra solo el pedazo que coincide, no la línea entera. Si una línea tiene dos coincidencias, salen las dos.
- `user_[0-9]*` es `user_` seguido de cualquier cantidad de dígitos: `[0-9]` es un dígito y `*` repite lo anterior.

Ahora, a contarlos:

<TerminalBlock title="vt@labs:~/lab-grep">

```bash
grep "ERROR" logs/*.log | grep -o "user_[0-9]*" | sort | uniq -c | sort -rn
```

</TerminalBlock>

```text
      2 user_42
      1 user_7
```

```text
sort       ordena, para que los repetidos queden juntos
uniq -c    junta los repetidos seguidos y cuenta cuántos hay
sort -rn   ordena por número (-n), de mayor a menor (-r)
```

`uniq` solo junta líneas iguales **seguidas**. Por eso va siempre después de `sort`.

<Callout type="comando">
  Poné el patrón entre comillas. Sin comillas, el shell puede interpretar
  `user_[0-9]*` como un patrón de nombres de archivo y reemplazarlo antes de
  que grep lo vea.
</Callout>

## Buscar en carpetas, solo en ciertos archivos: --include

<TerminalBlock title="vt@labs:~/lab-grep">

```bash
grep -r "ERROR" .
grep -r --include="*.log" "ERROR" .
```

</TerminalBlock>

```text
./logs/worker.log:2026-10-20 03:01:50 ERROR worker: falló la tarea 118 de user_42
./logs/app.log:2026-10-20 03:01:14 ERROR api: timeout al conectar con la base, user_42
./logs/app.log:2026-10-20 03:02:03 ERROR api: timeout al conectar con la base, user_7
./notas.txt:ERROR de prueba: no es un log, ignorar
```

```text
./logs/worker.log:2026-10-20 03:01:50 ERROR worker: falló la tarea 118 de user_42
./logs/app.log:2026-10-20 03:01:14 ERROR api: timeout al conectar con la base, user_42
./logs/app.log:2026-10-20 03:02:03 ERROR api: timeout al conectar con la base, user_7
```

`-r` recorre todas las carpetas y mete en la búsqueda a `notas.txt`, que no es un log. `--include="*.log"` limita la búsqueda a los archivos que terminan en `.log`. El orden de los archivos puede variar en tu máquina.
