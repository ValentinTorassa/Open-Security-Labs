Un README te dice `sudo apt install ./ragnaros_0.1.0-1_all.deb` y lo copiás. Ese comando corre como root scripts que no leíste y deja archivos en tu disco que no sabés cuáles son. Antes de instalar, abrilo: un `.deb` no es una caja negra, y se desarma con herramientas que ya tenés.

<Callout type="concepto">
  Un `.deb` tiene tres partes: `debian-binary` (la versión del formato),
  `control.tar` (la ficha del paquete y sus scripts) y `data.tar` (los archivos
  tal como van a quedar en tu disco, desde `/`). `dpkg` desarma e instala esas
  piezas; `apt` resuelve dependencias, baja los paquetes y se los pasa a
  `dpkg`.
</Callout>

## El paquete

En el entorno ya tenés `~/ragnaros_0.1.0-1_all.deb`, el paquete de la release v0.1.0 de [VT-Ragnaros](https://github.com/ValentinTorassa/VT-Ragnaros), un driver para un deck USB. Si lo hacés en tu máquina, bajalo y verificalo contra el SHA-256 que muestra la página de la release:

<TerminalBlock title="tu máquina">

```bash
curl -fLO https://github.com/ValentinTorassa/VT-Ragnaros/releases/download/v0.1.0/ragnaros_0.1.0-1_all.deb
echo "b02f9a7ace507cf50db51c6a853fab59c4638be7002c5d1f5986da66212d5ab2  ragnaros_0.1.0-1_all.deb" | sha256sum -c
```

</TerminalBlock>

```text
ragnaros_0.1.0-1_all.deb: OK
```

<Callout type="error">
  En tu máquina, no lo instales si no tenés el deck. Su `postinst` regenera tu
  initramfs y deja una opción para `usbhid`. Desarmarlo es seguro; instalarlo
  hacelo en el entorno.
</Callout>

## Un .deb es un archivo ar

`ar` es un formato de archivo de Unix más viejo que `tar`. Un `.deb` es uno con tres miembros:

<TerminalBlock title="vt@labs:~">

```bash
ar t ragnaros_0.1.0-1_all.deb
ar p ragnaros_0.1.0-1_all.deb debian-binary
```

</TerminalBlock>

```text
debian-binary
control.tar.gz
data.tar.gz
2.0
```

`2.0` es la versión del formato. La compresión cambia según quién arma el paquete: los de Debian suelen traer `.tar.xz`, los de Ubuntu `.tar.zst`, y este, armado con nfpm, `.tar.gz`. `dpkg` entiende los tres.

Son rutas desde `/`, con dueño `root/root` aunque el paquete lo haya armado un usuario común. Casi todo es Python en `/usr/lib/python3/dist-packages` (por eso `Architecture: all`). El resto son tres piezas de sistema, cada una en la carpeta donde la busca su programa:

```text
/usr/lib/udev/rules.d/    reglas que udev aplica cuando aparece un dispositivo
/usr/lib/modprobe.d/      opciones que modprobe le pasa a un módulo al cargarlo
/usr/lib/systemd/user/    unidades de systemd para la sesión de cada usuario
```

`/usr/lib` es del paquete. Si querés cambiar algo, el lugar es `/etc` con el mismo nombre de archivo (`/etc/udev/rules.d/70-ragnaros.rules`): udev, modprobe y systemd prefieren el de `/etc`, y el paquete nunca lo pisa.

Podés leer cualquier archivo sin instalar nada:

<TerminalBlock title="vt@labs:~">

```bash
dpkg-deb --fsys-tarfile ragnaros_0.1.0-1_all.deb | tar -xO ./usr/lib/udev/rules.d/70-ragnaros.rules
dpkg-deb --fsys-tarfile ragnaros_0.1.0-1_all.deb | tar -xO ./usr/lib/modprobe.d/ragnaros-usbhid.conf
```

</TerminalBlock>

```text
# Ragnaros deck (Redragon SS552, 0200:3001): let the logged-in user (uaccess)
# and the plugdev group open it through libusb. Numbered below 73 so the
# uaccess tag is seen by systemd-logind's seat rules.
SUBSYSTEM=="hidraw", ATTRS{idVendor}=="0200", ATTRS{idProduct}=="3001", GROUP="plugdev", MODE="0660", TAG+="uaccess"
SUBSYSTEM=="usb", ATTR{idVendor}=="0200", ATTR{idProduct}=="3001", GROUP="plugdev", MODE="0660", TAG+="uaccess"
# HID_QUIRK_IGNORE for the Ragnaros deck: usbhid leaves it alone so the
# daemon can claim both interfaces with libusb. Takes effect when usbhid
# loads (reboot, or regenerate the initramfs first where usbhid lives there).
options usbhid quirks=0x0200:0x3001:0x00000004
```

La regla de udev dice: cuando el kernel anuncia un dispositivo USB (o `hidraw`) con vendor `0200` y producto `3001`, creá su nodo en `/dev` con grupo `plugdev` y modo `0660`, y marcalo `uaccess` para que el usuario sentado en la máquina también pueda abrirlo. Sin esa regla, el nodo es de root y el daemon, que corre con tu usuario, no puede usarlo.

La línea de `modprobe.d` dice: cuando cargues `usbhid`, pasale `quirks=0x0200:0x3001:0x00000004`. `0x4` es `HID_QUIRK_IGNORE`: `usbhid` deja ese dispositivo en paz y `libusb` lo puede tomar. Como `usbhid` suele cargarse desde el initramfs, la opción tiene que estar ahí adentro.

## Los scripts corren como root

<TerminalBlock title="vt@labs:~">

```bash
dpkg-deb -e ragnaros_0.1.0-1_all.deb control
ls control
cat control/postinst
```

</TerminalBlock>

```text
control  md5sums  postinst  postrm  prerm
#!/bin/sh
set -e
if [ "$1" = "configure" ]; then
  if command -v py3compile >/dev/null 2>&1; then
    py3compile -p ragnaros || true
  fi
  if command -v udevadm >/dev/null 2>&1; then
    udevadm control --reload-rules || true
    udevadm trigger --subsystem-match=usb --attr-match=idVendor=0200 || true
  fi
  # usbhid loads from the initramfs: it has to carry the quirk
  if command -v update-initramfs >/dev/null 2>&1; then
    update-initramfs -u || true
  fi
  echo "ragnaros: reboot once so usbhid picks up the quirk, then as your user:"
  echo "ragnaros:   systemctl --user enable --now ragnarosd"
fi
exit 0
```

`dpkg` corre `postinst configure` después de copiar los archivos. Este compila el Python a `.pyc`, le pide a udev que relea las reglas y vuelva a mirar el deck, regenera el initramfs (reescribe un archivo en `/boot`) y te avisa que reinicies. Todo como root y sin preguntarte. `prerm` y `postrm` corren al desinstalar.

<Callout type="error">
  Un `.deb` de una fuente que no conocés es código que corre como root antes de
  que uses el programa. Antes de instalarlo, leé `preinst` y `postinst` (si
  están) y mirá qué rutas trae `data.tar`. Un driver de escritorio no necesita
  escribir en `/etc/sudoers.d` ni bajar nada de internet en su `postinst`.
</Callout>

## ¿Alguien tocó lo instalado?

`dpkg` guardó el `md5sums` del paquete. `dpkg --verify` compara cada archivo instalado contra ese hash:

<TerminalBlock title="vt@labs:~">

```bash
dpkg --verify ragnaros
sudo sed -i 's/MODE="0660"/MODE="0666"/' /usr/lib/udev/rules.d/70-ragnaros.rules
dpkg --verify ragnaros
```

</TerminalBlock>

```text
missing     /usr/share/doc/ragnaros/README.md
??5??????   /usr/lib/udev/rules.d/70-ragnaros.rules
missing     /usr/share/doc/ragnaros/README.md
```

La primera corrida solo marca el README como `missing`: la imagen slim de Debian no instala documentación (`path-exclude` en `/etc/dpkg/dpkg.cfg.d/docker`). En tu máquina esa línea no aparece.

La segunda agrega la regla: el `5` dice que su contenido ya no coincide con el MD5 del paquete (las demás columnas quedan en `?` porque `dpkg` hoy solo compara el MD5). Ese cambio no es inocente: con `0666`, cualquier usuario de la máquina puede hablarle al deck. `dpkg --verify` sale con `0` aunque encuentre diferencias, así que lo que cuenta es lo que imprime.

Para volver al estado del paquete, reinstalalo:

<TerminalBlock title="vt@labs:~">

```bash
sudo dpkg -i ragnaros_0.1.0-1_all.deb
dpkg --verify ragnaros
```

</TerminalBlock>

```text
(Reading database ... 6951 files and directories currently installed.)
Preparing to unpack ragnaros_0.1.0-1_all.deb ...
Unpacking ragnaros (0.1.0-1) over (0.1.0-1) ...
Setting up ragnaros (0.1.0-1) ...
ragnaros: reboot once so usbhid picks up the quirk, then as your user:
ragnaros:   systemctl --user enable --now ragnarosd
missing     /usr/share/doc/ragnaros/README.md
```

`dpkg` vuelve a desempaquetar encima (`over (0.1.0-1)`) y vuelve a correr el `postinst`. La regla quedó como vino.

<Callout type="nota">
  `sudo dpkg -r ragnaros` lo desinstala (corre `prerm` y `postrm`), pero queda
  en estado `config-files` porque tiene `postrm`; `sudo dpkg -P ragnaros` lo
  purga del todo. Para `lab-check`, dejalo instalado.
</Callout>
